# 教学：让读者能重新推导

成功标准不是讲完知识点。读者忘掉文件名和 API 后，仍能从模型推出方向。

## 五种能力（缺一则只是信息传递）

1. Predict：改一个条件，系统大概怎样变  
2. Diagnose：异常大概在哪一层  
3. Decide：比方案时比什么  
4. Transfer：换框架还能认出同一机制  
5. Delegate：什么交给 Agent、什么留在人、如何验收  

## 一篇一个认知变化

先写：读前相信什么，读后能多做什么判断。其余材料为这个变化服务。

## 最小充分理解

Why / Responsibility（尤其不负责什么）/ Input-Output / State（谁改）/ Relation / Replace。

答不出这六问，不得当读者已经理解。

## 术语许可证

标题、封面、Hook、前置问题禁止公布目标术语。须先走过：问题→失败→约束→拆责任→机制→判断。读者能回答为什么/负责/不负责/和谁有关/没有会怎样，才允许命名。

## 叙事

问题 → 最小方案 → 真实压力 → 原方案失效 → 拆责任 → 机制 → 比较 → 观察 → 最后命名。

顺序：Concept → Architecture → Implementation。不要按源码目录讲。

## 代码与图

禁止把代码译成中文逐行。用系统语言：事件、主体、状态、控制权、结果、下一站。

自然语言、图、代码必须同构。图只画当前认知目标；标题最好是问题（谁决定下一步？事实放哪？）。

五个元素尽量都在：Anchor / Model / Mechanism / Boundary / Transfer。
